# 빠른 시작

[English](QUICKSTART.md) · 한국어

이 안내는 로컬 관측 콘솔을 실행하고 합성 샘플 이벤트를 분석한 뒤 실제 센서를 연결하는 과정을 설명합니다. 베타 기본 설정에서는 자동 차단과 호스트 격리가 꺼져 있습니다. Linux 단일 호스트 연동과 Windows 로컬 콘솔 평가 패키지의 범위는 [베타 범위](BETA-SCOPE.ko.md)를 참고하세요.

## 1. 설치 또는 빌드

신뢰할 수 있는 배포자가 운영체제에 맞는 베타 압축본을 제공한 경우 그 파일을 사용하세요. 공개 다운로드 링크는 배포 여부에 따라 달라집니다. 쓰기 가능한 로컬 폴더에 압축본 전체를 풀고, 설정 예제와 문서를 실행 파일과 같은 폴더에 두세요. 실행하기 전에 배포자가 게시한 체크섬 값과 대조하세요. 직접 압축본을 만들려면 [릴리스 패키징 안내(영문)](RELEASING.md)를 참고하세요.

소스에서 빌드하려면 **Go 1.26 이상**을 설치하고 저장소 루트에서 아래 명령을 실행하세요. 첫 빌드 때는 Go 모듈을 내려받을 수 있습니다. 운영체제에 맞는 실행 파일을 사용하세요.

**Windows PowerShell**

```powershell
.\build.bat
.\start.bat
```

**Linux**

```sh
sh build.sh
sh start.sh
```

미리 빌드된 압축본에서는 Windows PowerShell에서 `.\start.bat`, Linux에서 `sh start.sh`만 실행하세요. 배포 대상은 **Windows amd64와 Linux amd64**입니다. 운영체제와 아키텍처가 모두 일치하는 실행 파일을 사용하세요. 이 기본 과정에는 Go, Python, Node.js, 데이터베이스, LLM을 설치할 필요가 없습니다. macOS에서 셸 스크립트로 빌드할 수 있지만 이번 베타의 실행 검증 범위에서는 제외됩니다.

실행용 압축본에는 실행 파일, 일부 연동 소스와 설정 예제, 사용자 문서가 포함됩니다. Go 전체 소스, 빌드 스크립트, Docker 프로필과 나머지 개발·검증 보고서는 소스 체크아웃에서 확인하세요. 빌드, `go run ./cmd/...` 실행, Docker 프로필 사용에는 소스 체크아웃이 필요합니다. 압축본 안의 문서에는 소스에서만 볼 수 있는 과거 기록을 따로 표시합니다. [검증 요약(영문)](VALIDATION.md)에 베타 시험 측정값이 있으며, 배포 압축본 자체에 대한 검증 결과는 기능 시험과 별도로 기록합니다.

## 2. 콘솔 접속과 확인

프로세스가 출력한 전체 URL을 `#token=...`까지 포함해 여세요. 기본 주소는 `http://127.0.0.1:9081`입니다. 접속 URL을 비공개로 보관하세요. 주소만 열었다면 콘솔 접속 키도 입력해야 합니다.

처음 실행하면 애플리케이션 폴더에 `config.json`과 `data/collector/`가 만들어집니다. 센서 토큰은 설정에 유지되며 콘솔 접속 키는 재시작할 때마다 바뀝니다. **개요**에서 수집 상태를 확인하세요. 센서를 연결하기 전에는 이벤트 목록이 비어 있습니다. 수집 프로세스가 실행 중인 터미널을 열어 두세요.

다른 로컬 프로그램이 이 포트를 쓰고 있다면 수집기를 중지한 뒤 다른 루프백 포트를 지정하세요.

```powershell
.\start.bat -listen 127.0.0.1:9091
```

Linux에서는 `sh start.sh -listen 127.0.0.1:9091`을 실행하세요. 새로 출력된 URL로 접속하세요. 같은 데이터 경로를 쓰는 수집기를 동시에 두 개 실행하면 안 됩니다.

## 3. 샘플과 파일 분석

1. **파일 분석**을 여세요.
2. **샘플 12건으로 기능 확인**을 선택하세요. 이벤트 12건이 분석됐고 정책 실행이 0건인지 확인한 뒤 탐지 근거를 살펴보세요.
3. 파일 업로드를 확인하려면 [http-sample.jsonl](examples/http-sample.jsonl)을 저장한 뒤 파일을 선택하고 **파일 분석 시작**을 누르세요. 이 파일에는 정규화된 합성 HTTP 데이터가 들어 있습니다.
4. 자체 데이터를 분석하려면 [센서 스키마](SENSOR.md)에 맞춰 줄마다 완전한 이벤트를 하나씩 넣으세요. 한도는 파일당 1 MiB, 이벤트 1,024건, 레코드당 16 KiB입니다. 파일 분석은 기록된 `ingest_time`을 사용하므로 시간순으로 정렬된 과거 데이터를 분석할 수 있습니다.

샘플과 파일은 별도 메모리에서 분석됩니다. 결과는 실시간 **이벤트**, **경보**, **사건 기억**에 저장되지 않으며 Ollama 호출이나 정책 적용도 일어나지 않습니다. 규칙에 필요한 정보가 빠지면 경보가 없을 수 있습니다.

## 4. 허가받은 HTTP 센서 연결

**연결 설정**에서 등록된 센서 ID, 자산, 테넌트 목록, 센서 토큰을 확인하세요. 기본 예제의 센서 ID는 `lab-app`, 자산은 `lab-api`, 테넌트는 `alpha`, `beta`, `public`입니다. 애플리케이션이나 WAF 어댑터가 관측 데이터를 정규화하고 등록된 범위에 맞춰 보내야 합니다.

`Content-Type: application/json`과 `Authorization: Bearer <비공개 센서 토큰>` 헤더를 사용해 `POST http://127.0.0.1:9081/v1/events`로 JSON 이벤트를 보내세요. 일괄 입력은 JSON 배열을 `/v1/events/batch`로 보냅니다. 시계를 동기화하세요. 실시간 이벤트 시각은 허용된 한 시간 범위에 들어야 합니다. 시간이 고정된 샘플 파일은 **파일 분석**에 사용하세요.

어댑터를 구현하기 전에 [센서 계약](SENSOR.md)에서 필수 필드, HMAC 식별자, 상태 코드, 호스트 이벤트 분리 조건을 확인하세요. 수집 후 **개요**, **이벤트**, **경보**에서 수집 상태와 결과를 확인하세요. 정책을 적용하려면 센서 연동 외에 별도 설정이 필요합니다.

## 5. 선택 사항인 로컬 모델 조사

기존 로컬 Ollama 서비스를 실행하세요. 기본 주소는 `http://127.0.0.1:11434`입니다. 도구 호출을 지원하는 모델을 별도로 설치하고 평가하세요. 하드웨어 요구 사항은 모델에 따라 달라집니다.

수집한 경보를 조사하려면 **사건 기억**에서 **수집 증거 동기화**를 누르고 사건을 선택하세요. **Qwen 조사**에서 설치된 모델을 선택한 뒤 **사건 분석 시작**을 누르세요. 모델이 인용한 증거와 검증된 도구 결과를 확인하세요. 기본 동작은 분석이며, 확정 라벨 생성이나 모델 학습은 수행하지 않습니다. **Qwen 조사**에서 Qwen 외에 지원되는 로컬 모델도 선택할 수 있습니다.

조사를 취소하면 실행 중인 조사가 멈춥니다. 이미 적용된 선택 정책은 별도로 철회해야 합니다. 대응 자격 증명을 설정하기 전에 [로컬 조사와 제한 대응 안내](LOCAL-QWEN.md)를 읽으세요. 파일 분석 샘플은 이 기능에서 조사할 사건을 생성하지 않습니다.

## 6. 종료, 백업 및 재시작

실행 중인 터미널에서 **Ctrl+C**를 누르고 프로세스가 종료될 때까지 기다리세요. 중지 상태에서 비공개 `config.json`과 `data/` 디렉터리 전체를 함께 백업하세요. 같은 시작 스크립트로 다시 실행하고 새 접속 URL을 여세요. 증거 디렉터리 하나에 쓰기 프로세스는 하나만 실행하세요.

시작할 때 증거 또는 복구 관련 오류가 표시되면 원본 파일과 로그를 보존하세요. 프로세스를 중지한 상태에서 아래 명령으로 콘솔을 열지 않고 기본 수집기 저장소를 검사할 수 있습니다.

```powershell
.\reverse-artex.exe -recover-check -out data/collector
```

Linux에서는 `./reverse-artex -recover-check -out data/collector`를 사용하세요. 별도로 설정한 공유 저장소나 정책 상태는 해당 절차를 따라 점검하세요. 복구 오류가 나면 원본 데이터를 보존하고 [운영 안내](OPERATIONS.md)에서 복구, 용량, 설정 우선순위, 선택 서비스, API 전용 Docker 프로필을 확인하세요.

## 7. 선택 CLI 도구

시작 스크립트는 콘솔과 수집기만 실행합니다. 선택 서비스와 관리 도구는 `bin/`에 있습니다. 설정하기 전에 도구 도움말과 연동 계약을 읽으세요. 다음 예시는 압축을 푼 폴더나 소스를 빌드한 프로젝트 루트에서 실행합니다.

**Windows PowerShell**

```powershell
.\bin\policy-edge.exe -h
```

**Linux**

```sh
./bin/policy-edge -h
```

소스용 가이드에 `go run ./cmd/policy-edge`가 나오면 환경에 맞는 실행 파일을 사용하고, 현재 도움말에서 지원하는 인수만 전달하세요. 정책 서비스를 시작한 뒤에도 애플리케이션 트래픽을 연결하고 접근 권한 검사를 연동해야 보호 기능을 사용할 수 있습니다. [운영 안내](OPERATIONS.md) · [제공 기능](CAPABILITIES.md)

## 처음 실행할 때 자주 발생하는 문제

| 증상 | 확인할 사항 |
| --- | --- |
| 실행 파일을 찾을 수 없음 | 현재 운영체제용으로 빌드하거나 운영체제와 아키텍처에 맞는 압축본 전체를 푸세요. |
| 브라우저에서 접속할 수 없음 | 프로세스가 실행 중인지 확인하고 방금 출력된 주소와 포트를 사용하세요. 터미널에 표시된 시작 오류를 확인하세요. |
| 콘솔 접속 거부 | 현재 프로세스가 출력한 전체 접속 URL을 여세요. 이전 실행의 콘솔 키와 센서 토큰은 현재 콘솔 키와 별개입니다. |
| 실시간 입력이 400/403을 반환 | 전체 스키마, 이벤트 시각, 등록된 센서·테넌트·자산 범위를 확인하세요. |
| 샘플 분석 후 이벤트 목록이 비어 있음 | 예상된 동작입니다. 샘플·파일 분석은 수집 원장에 기록되지 않습니다. 권한을 받은 실제 어댑터를 연결하세요. |
| Ollama에 연결할 수 없거나 사용할 모델이 없음 | 기본 수집은 계속 사용할 수 있습니다. 로컬 서비스를 실행하고 이미 설치된 도구 지원 모델을 선택하세요. |
| 저장소가 가득 찼거나 복구 실패 | 프로세스를 중지하고 원본 데이터를 보존한 뒤 [운영 안내](OPERATIONS.md)를 확인하세요. |

로컬 환경을 확장하기 전에 [지원 환경과 한계(영문)](COMPATIBILITY.md)와 [보안 정책](../SECURITY.ko.md)을 읽으세요.
